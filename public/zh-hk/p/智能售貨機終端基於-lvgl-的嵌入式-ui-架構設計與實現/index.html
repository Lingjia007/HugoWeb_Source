前言

在物聯網終端設備中，交互體驗往往是產品競爭力的關鍵。本文將介紹一個基於 ArtInChip 嵌入式平台 + LVGL v8 + RT-Thread 的智能售貨機終端 UI 系統的完整設計與實現。項目由 AiUIBuilder v2.0.2 生成的靜態 UI 骨架 + 手工編寫的動態業務邏輯組成，實現了從"所見即所得"的可視化原型到可交互動態應用的平滑過渡。

一、系統架構

1.1 項目組成

項目分為兩大模組：

目錄 職責 來源
ui_builder/ 屏幕佈局、靜態控件、樣式和字體 AiUIBuilder 自動生成
my_custom_init/ 交互邏輯、數據綁定、通信和動態加載 手工編寫

my_custom_init/ 內部的模組層次如下：

層級 模組 職責
基礎設施層 event_bus 發布-訂閱解耦通信
基礎設施層 async_loader 工作線程 + LVGL 定時器回調
佈局框架層 layout_node 組合模式的 UI 節點樹
佈局框架層 layout_strategy Flex/Grid 佈局策略映射
組件工廠層 component_factory 組裝完整 UI 組件
組件工廠層 widget_factory 按類型名註冊/創建控件
控件層 banner_carousel / banner_item 橫幅輪播控制器
控件層 commodity_card 商品展示與加購
控件層 cart_item 購物車狀態管理
控件層 navi_item 導航欄選項卡
業務層 custom_init 組裝所有模組
業務層 web_config WiFi AP + HTTP 配置頁面
業務層 uart3_payment UART3 通信 + 支付流程
業務層 qr_scanner DVP 攝像頭 + quirc 解碼

1.2 設計模式

項目中運用了多種經典設計模式：

  • 組合模式 (Composite)：layout_node 框架將 Container 和 Widget 統一為樹形結構，通過 destroy() 虛函數實現深度優先銷毀。
  • 工廠模式 (Factory)：widget_factory 按類型名字符串註冊創建函數，支持 banner_item、commodity_card、cart_item、navi_item 四種控件的動態創建。
  • 發布-訂閱模式 (Pub-Sub)：event_bus 實現輕量級事件總線，組件間通過事件解耦。
  • 策略模式 (Strategy)：layout_strategy_t 封裝佈局類型和參數，通過 layout_strategy_apply() 映射到 LVGL Flex API。
  • 對象池模式 (Object Pool)：使用 RT-Thread 內存池 (rt_mp_create/rt_mp_alloc/rt_mp_free) 管理高頻分配的控件數據，避免內存碎片。

二、事件驅動架構

2.1 事件總線設計

event_bus 維護一個 s_slots[EVT_TYPE_MAX] 數組，每個槽位最多 8 個訂閱者，使用 RT-Thread 互斥鎖保證線程安全。

event_bus_publish() 在發布時先快照訂閱者列表再釋放鎖後逐一回調，避免回調中修改訂閱導致的迭代問題。

2.2 核心事件流

定義了 8 種事件類型：購物車增/刪/數量變/價格變、Banner/商品/導航配置變更、導航點擊。

典型事件流如下：

  1. 商品加購：commodity_card 點擊加購按鈕 → 發布 EVT_CART_ITEM_ADDED → cart_item 模組訂閱處理 → 發布 EVT_CART_COUNT_CHANGED + EVT_CART_PRICE_CHANGED
  2. 購物車數量變化：+/- 按鈕點擊 → 修改 count → 更新總價標籤和數量角標
  3. Web 配置變更：HTTP POST → 設置待處理標誌 → LVGL 定時器輪詢 → 發布 EVT_BANNER_CONFIG_CHANGED 等事件 → 各組件熱更新
  4. 導航點擊：navi_item 點擊 → 發布 EVT_NAVI_ITEM_CLICKED

2.3 跨線程通信

通信路徑 機制 說明
UART3 RX 線程 → LVGL 線程 無鎖 SPSC 環形隊列 + LVGL 定時器 (100ms) RX 線程只解析幀入隊，絕不調用 LVGL API
Web 配置線程 → LVGL 線程 volatile 標誌 + 緩衝區 + LVGL 定時器 (200ms) HTTP 線程只寫緩衝區，定時器在 LVGL 線程發布事件
QR 掃描線程 → UART3 rt_device_write() 線程安全的串口寫入

3.4 動畫效果

  • 按鈕縮放動畫：點擊時 zoom 從 256 縮至 210，使用 lv_anim_path_overshoot 回彈，100ms 下壓 + 200ms 回彈。
  • 購物車面板滑入/滑出：Y 座標從 480（屏幕外）動畫至 70（可見），400ms linear；同時配合透明度漸變。
  • 輪播翻頁：lv_obj_scroll_to_x 動畫，600ms ease_out。

四、輪播橫幅模組

4.1 架構設計

輪播模組採用控制器-視圖分離設計：

  • banner_types.h：純數據類型定義，無 UI 依賴
  • banner_carousel：不創建也不擁有容器和子控件，只附加控制器行為
  • banner_item：簡單圖片控件，從內存池分配

4.2 核心功能

  • 自動滾動：定時器驅動，可暫停/恢復
  • 滑動手勢檢測：基於 scroll_begin_cb / scroll_end_cb，比較 scroll_x 差值與 switch_threshold 閾值判斷翻頁
  • 指示器圓點：延遲 50ms 創建，避免佈局未完成時位置錯誤
  • 數據熱更新：banner_carousel_update_data() 暫停定時器 → 清除子控件 → 重建 → 重建圓點 → 恢復定時器

五、購物車系統

5.1 商品卡片

每個卡片包含：商品圖片 (80×80)、名稱標稱標籤、價格標籤、加購按鈕、標籤角標（熱賣/新品/推薦）。

commodity_card_batch_update() 實現差異更新：按需增刪卡片數量，然後逐一 update() 數據，支持 Grid 佈局自動換行。內存池容量 = COMMODITY_MAX_COUNT (30)。

5.2 購物車項

  • cart_add_commodity() 先按名稱搜索已有項，找到則增加數量，否則創建新項
  • 減到 0 時自動移除並發布 EVT_CART_ITEM_REMOVED 事件
  • cart_update_total_price() 遍歷所有項，解析價格字符串（跳過貨幣前綴），計算 count * price_val 總和
  • cart_update_count_tag() 管理購物車圖標上的數量角標

6.2 雙支付模式

模式一：用戶掃碼

  1. 用戶點擊結算按鈕 → 解析購物車總價 → 顯示支付模式選擇彈窗
  2. 用戶選擇"用戶掃碼" → 發送 CMD_REQ_QR 到 PC
  3. PC 生成支付寶沙箱訂單，返回 CMD_QR_URL
  4. 設備顯示 QR 碼覆蓋層（240×240，LVGL lv_qrcode 控件）
  5. PC 輪詢支付狀態後返回 CMD_PAY_STATUS
  6. 成功：顯示"支付成功!"，2 秒後自動隱藏，清空購物車，恢復輪播

模式二：設備掃備掃碼（條碼支付）

  1. 用戶選擇"設備攝像頭掃碼"
  2. 啟動 DVP 攝像頭 + quirc 掃描線程
  3. 設置 UI 層 alpha=128 使視頻層透視顯示
  4. quirc 掃描到 18~28 位純數字（支付授權碼）後，通過 CMD_BARCODE_PAY 發送至 PC
  5. PC 調用支付寶條碼支付 API，返回支付狀態
  6. 成功後流程同上

6.3 線程安全設計

UART3 RX 線程嚴格不調用任何 LVGL API。幀解析完成後僅入隊到 SPSC 環形緩衝區。LVGL 定時器 (100ms) 在 LVGL 線程上下文出隊處理，確保所有 UI 操作的線程安全。

七、二維碼掃描模組

7.1 硬件配置

  • DVP 攝像頭 (OV5640)，強制 QVGA 320×240 輸出，降低內存佔用（約 460KB）
  • ArtInChip 視頻輸入框架 (mpp_vin, drv_dvp)
  • Framebuffer 視頻層 (mpp_fb) 用於攝像頭預覽
  • quirc QR 碼解碼庫

7.2 掃描流程

  1. qr_scanner_start()：初始化 DVP（含 5 次重試容錯）、配置傳感器格式、創建 quirc 實例 (160×120，2 倍下采樣)
  2. 掃描線程循環：dq_buf → 丟棄前幾幀 → 每 5 幀提取 Y 通道並下采樣 → quirc_decode
  3. handle_qr_result()：檢測是否為支付授權碼（18~28 位純數字），同碼 5 秒冷卻，調用 uart3_payment_send_barcode() 發送

7.3 攝像頭視圖模式

通過 ArtInChip framebuffer 的視頻層直接顯示 DVP 採集幀：

  • qr_scanner_start_camera_view()：打開 framebuffer，設置 UI 層 alpha=128
  • DVP 緩衝區零拷貝推送到視頻層，實現高性能畫中畫效果
  • 停止時嚴格順序：清標誌 → 停掃描線程 → 停 DVP 流 → 等線程退出 → 禁用視頻層 + 恢復 UI alpha → 釋放資源

7.4 內存管理

  • 灰度緩衝區從 CMA 分配：aicos_malloc(MEM_CMA, scan_w * scan_h)
  • 下采樣算法：2×2 區域取均值，將 320×240 降至 160×120 供 quirc 處理
  • Y 通道提取後立即釋放 DVP 緩衝區回隊列，避免佔用過久

八、Web 配置系統

8.1 架構

設備啟動 WiFi AP（SSID: AIC-Banner-Config，密碼: 12345678，信道 6），IP 地址 192.168.1.1，運行 DHCP 伺服器，在 80 端口啟動 Mongoose HTTP 伺服器。

8.2 API 接口

方法 路徑 功能
GET / 嵌入式 HTML 配置頁面
GET /api/config 獲取 Banner 配置 JSON
GET /api/commodity 獲取商品配置 JSON
GET /api/navi 獲取導航配置 JSON
POST /api/config 更新 Banner 配置
POST /api/commodity 更新商品配置
POST /api/navi 更新導航配置

8.3 安全措施

  • 文件名白名單校驗：僅允許字母、數字、.、_、-，長度不超過 64
  • Content-Length 早期拒絕：超限直接返回 413
  • 接收緩衝區限制：recv_mbuf.len > 307200 + 4096 時強制關閉連接
  • 圖片尺寸校驗：解析 PNG/JPEG/BMP 文件頭驗證寬高，不匹配則刪除並返回錯誤
  • 價格格式校驗：支持多種貨幣前前綴，驗證必須包含數字和可選小數部分

8.4 配置熱更新

  1. HTTP 線程接收 POST → 解析 JSON → 寫入 s_pending_json 緩衝區 → 設置標誌
  2. 同時將 JSON 保存到 SD 卡文件實現持久化
  3. LVGL 定時器 200ms 輪詢檢測標誌 → 發布事件 → 各組件執行熱更新

十、系統初始化流程

custom_init() 是整個系統的組統的組裝入口，執行以下初始化序列：

  1. 初始化基礎設施：event_bus、async_loader
  2. 初始化所有控件模組的對象池
  3. 等待 SD 卡掛載（最多重試 50 次，每次 100ms）
  4. 複製默認圖片資源從 /rodata/image 到 /sdcard
  5. 初始化 TTF 字體（思源黑體 15/18 號）
  6. 註冊四種控件到 widget_factory
  7. 刪除 AiUIBuilder 生成的靜態控件，替換為動態組件
  8. 創建四大組件（banner、commodity、cart、navi）
  9. 綁定購物車動畫、結算按鈕事件
  10. 訂閱 Web 配置變更事件
  11. 啟動 Web 配置伺服器、UART3 支付模組、QR 掃描模組
  12. 加載持久化配置（覆蓋默認值）

十一、技術亮點總結

  1. AiUIBuilder + 自定義代碼橋接：通過 layout_container_wrap() 將工具創建的 LVGL 對象包裝為動態佈局容器，既保留可視化快速原型能力，又獲得運行時靈活性。

  2. 全事件驅動架構：組件間零直接依賴，購物車不知道商品卡片的實現，支付模組不知道購物車的實現，Web 配置不知道任何 UI 組件的 API。

  3. 嵌入式 Web 配置：RT-Thread 上運行 Mongoose HTTP 伺服器 + WiFi AP，手機連接熱點即可修改配置，無需固件升級，配置自動持久化到 SD 卡。

  4. 雙支付模式：支持"用戶掃碼"和"設備掃碼"兩種模式，通過 UART3 與 PC 主機通信，實現支付寶沙箱環境下的完整支付閉環。

  5. 無鎖線程間通信：UART3 使用 SPSC 環形隊列，Web 配置使用 volatile 標誌 + 緩衝區，均避免重量級鎖開銷。

  6. 內存池管理：所有高頻創建/銷毀的控件使用 RT-Thread 內存池，容量與業務上限對齊，避免內存碎片。

  7. 攝像頭視圖硬件加速：DVP 緩衝區零拷貝推送到視頻層，UI 層半透明實現畫中畫效果。

  8. 組合模式 UI 樹：Container 和 Widget 統一為樹形結構，支持深度優先銷毀、批量更新、動態增刪，使運行時熱更新簡單可靠。
