前言

在物联网终端设备中，交互体验往往是产品竞争力的关键。本文将介绍一个基于 ArtInChip 嵌入式平台 + LVGL v8 + RT-Thread 的智能售货机终端 UI 系统的完整设计与实现。项目由 AiUIBuilder v2.0.2 生成的静态 UI 骨架 + 手工编写的动态业务逻辑组成，实现了从"所见即所得"的可视化原型到可交互动态应用的平滑过渡。

一、系统架构

1.1 项目组成

项目分为两大模块：

目录 职责 来源
ui_builder/ 屏幕布局、静态控件、样式和字体 AiUIBuilder 自动生成
my_custom_init/ 交互逻辑、数据绑定、通信和动态加载 手工编写

my_custom_init/ 内部的模块层次如下：

层级 模块 职责
基础设施层 event_bus 发布-订阅解耦通信
基础设施层 async_loader 工作线程 + LVGL 定时器回调
布局框架层 layout_node 组合模式的 UI 节点树
布局框架层 layout_strategy Flex/Grid 布局策略映射
组件工厂层 component_factory 组装完整 UI 组件
组件工厂层 widget_factory 按类型名注册/创建控件
控件层 banner_carousel / banner_item 横幅轮播控制器
控件层 commodity_card 商品展示与加购
控件层 cart_item 购物车状态管理
控件层 navi_item 导航栏选项卡
业务层 custom_init 组装所有模块
业务层 web_config WiFi AP + HTTP 配置页面
业务层 uart3_payment UART3 通信 + 支付流程
业务层 qr_scanner DVP 摄像头 + quirc 解码

1.2 设计模式

项目中运用了多种经典设计模式：

  • 组合模式 (Composite)：layout_node 框架将 Container 和 Widget 统一为树形结构，通过 destroy() 虚函数实现深度优先销毁。
  • 工厂模式 (Factory)：widget_factory 按类型名字符串注册创建函数，支持 banner_item、commodity_card、cart_item、navi_item 四种控件的动态创建。
  • 发布-订阅模式 (Pub-Sub)：event_bus 实现轻量级事件总线，组件间通过事件解耦。
  • 策略模式 (Strategy)：layout_strategy_t 封装布局类型和参数，通过 layout_strategy_apply() 映射到 LVGL Flex API。
  • 对象池模式 (Object Pool)：使用 RT-Thread 内存池 (rt_mp_create/rt_mp_alloc/rt_mp_free) 管理高频分配的控件数据，避免内存碎片。

二、事件驱动架构

2.1 事件总线设计

event_bus 维护一个 s_slots[EVT_TYPE_MAX] 数组，每个槽位最多 8 个订阅者，使用 RT-Thread 互斥锁保证线程安全。

typedef struct {

static event_slot_t s_slots[EVT_TYPE_MAX];

event_bus_publish() 在发布时先快照订阅者列表再释放锁后逐一回调，避免回调中修改订阅导致的迭代问题。

2.2 核心事件流

定义了 8 种事件类型：购物车增/删/数量变/价格变、Banner/商品/导航配置变更、导航点击。

典型事件流如下：

  1. 商品加购：commodity_card 点击加购按钮 → 发布 EVT_CART_ITEM_ADDED → cart_item 模块订阅处理 → 发布 EVT_CART_COUNT_CHANGED + EVT_CART_PRICE_CHANGED
  2. 购物车数量变化：+/- 按钮点击 → 修改 count → 更新总价标签和数量角标
  3. Web 配置变更：HTTP POST → 设置待处理标志 → LVGL 定时器轮询 → 发布 EVT_BANNER_CONFIG_CHANGED 等事件 → 各组件热更新
  4. 导航点击：navi_item 点击 → 发布 EVT_NAVI_ITEM_CLICKED

2.3 跨线程通信

通信路径 机制 说明
UART3 RX 线程 → LVGL 线程 无锁 SPSC 环形队列 + LVGL 定时器 (100ms) RX 线程只解析帧入队，绝不调用 LVGL API
Web 配置线程 → LVGL 线程 volatile 标志 + 缓冲区 + LVGL 定时器 (200ms) HTTP 线程只写缓冲区，定时器在 LVGL 线程发布事件
QR 扫描线程 → UART3 rt_device_write() 线程安全的串口写入

关键设计：layout_container_wrap() 可将 AiUIBuilder 生成的已有 LVGL 对象包装为 layout_container，保留外部对象所有权，仅挂载子管理逻辑。这使得动态组件可以复用可视化工具创建的容器。

3.2 布局策略

layout_strategy_t 封装布局类型和参数，映射为 LVGL Flex API 调用：

策略 实现 用途
Flex-Row LV_FLEX_FLOW_ROW 横幅轮播、导航栏
Flex-Column LV_FLEX_FLOW_COLUMN 购物车列表
Grid LV_FLEX_FLOW_ROW_WRAP + FLEX_IN_NEW_TRACK 商品展示区 (3列)

3.3 屏幕分区

800×480 屏幕分为四大区域：

区域 位置 尺寸 组件
横幅轮播区 (153, 12) 494×78 banner (flex-row, 水平滚动)
导航栏 (16, 102) 768×45 navi (flex-row, 不可滚动)
商品展示区 (0, 150) 800×220 commodity (grid 3列, 垂直滚动)
购物车面板 (0, 70/480) 800×410 cart (flex-column, 垂直滚动)

3.4 动画效果

  • 按钮缩放动画：点击时 zoom 从 256 缩至 210，使用 lv_anim_path_overshoot 回弹，100ms 下压 + 200ms 回弹。
  • 购物车面板滑入/滑出：Y 坐标从 480（屏幕外）动画至 70（可见），400ms linear；同时配合透明度渐变。
  • 轮播翻页：lv_obj_scroll_to_x 动画，600ms ease_out。

四、轮播横幅模块

4.1 架构设计

轮播模块采用控制器-视图分离设计：

  • banner_types.h：纯数据类型定义，无 UI 依赖
  • banner_carousel：不创建也不拥有容器和子控件，只附加控制器行为
  • banner_item：简单图片控件，从内存池分配

4.2 核心功能

  • 自动滚动：定时器驱动，可暂停/恢复
  • 滑动手势检测：基于 scroll_begin_cb / scroll_end_cb，比较 scroll_x 差值与 switch_threshold 阈值判断翻页
  • 指示器圆点：延迟 50ms 创建，避免布局未完成时位置错误
  • 数据热更新：banner_carousel_update_data() 暂停定时器 → 清除子控件 → 重建 → 重建圆点 → 恢复定时器

五、购物车系统

5.1 商品卡片

每个卡片包含：商品图片 (80×80)、名称标签、价格标签、加购按钮、标签角标（热卖/新品/推荐）。

commodity_card_batch_update() 实现差异更新：按需增删卡片数量，然后逐一 update() 数据，支持 Grid 布局自动换行。内存池容量 = COMMODITY_MAX_COUNT (30)。

5.2 购物车项

  • cart_add_commodity() 先按名称搜索已有项，找到则增加数量，否则创建新项
  • 减到 0 时自动移除并发布 EVT_CART_ITEM_REMOVED 事件
  • cart_update_total_price() 遍历所有项，解析价格字符串（跳过货币前缀），计算 count * price_val 总和
  • cart_update_count_tag() 管理购物车图标上的数量角标

6.2 双支付模式

模式一：用户扫码

  1. 用户点击结算按钮 → 解析购物车总价 → 显示支付模式选择弹窗
  2. 用户选择"用户扫码" → 发送 CMD_REQ_QR 到 PC
  3. PC 生成支付宝沙箱订单，返回 CMD_QR_URL
  4. 设备显示 QR 码覆盖层（240×240，LVGL lv_qrcode 控件）
  5. PC 轮询支付状态后返回 CMD_PAY_STATUS
  6. 成功：显示"支付成功!"，2 秒后自动隐藏，清空购物车，恢复轮播

模式二：设备扫码（条码支付）

  1. 用户选择"设备摄像头扫码"
  2. 启动 DVP 摄像头 + quirc 扫描线程
  3. 设置 UI 层 alpha=128 使视频层透视显示
  4. quirc 扫描到 18~28 位纯数字（支付授权码）后，通过 CMD_BARCODE_PAY 发送至 PC
  5. PC 调用支付宝条码支付 API，返回支付状态
  6. 成功后流程同上

6.3 线程安全设计

UART3 RX 线程严格不调用任何 LVGL API。帧解析完成后仅入队到 SPSC 环形缓冲区。LVGL 定时器 (100ms) 在 LVGL 线程上下文出队处理，确保所有 UI 操作的线程安全。

七、二维码扫描模块

7.1 硬件配置

  • DVP 摄像头 (OV5640)，强制 QVGA 320×240 输出，降低内存占用（约 460KB）
  • ArtInChip 视频输入框架 (mpp_vin, drv_dvp)
  • Framebuffer 视频层 (mpp_fb) 用于摄像头预览
  • quirc QR 码解码库

7.2 扫描流程

  1. qr_scanner_start()：初始化 DVP（含 5 次重试容错）、配置传感器格式、创建 quirc 实例 (160×120，2 倍下采样)
  2. 扫描线程循环：dq_buf → 丢弃前几帧 → 每 5 帧提取 Y 通道并下采样 → quirc_decode
  3. handle_qr_result()：检测是否为支付授权码（18~28 位纯数字），同码 5 秒冷却，调用 uart3_payment_send_barcode() 发送

7.3 摄像头视图模式

通过 ArtInChip framebuffer 的视频层直接显示 DVP 采集帧：

  • qr_scanner_start_camera_view()：打开 framebuffer，设置 UI 层 alpha=128
  • DVP 缓冲区零拷贝推送到视频层，实现高性能画中画效果
  • 停止时严格顺序：清标志 → 停扫描线程 → 停 DVP 流 → 等线程退出 → 禁用视频层 + 恢复 UI alpha → 释放资源

7.4 内存管理

  • 灰度缓冲区从 CMA 分配：aicos_malloc(MEM_CMA, scan_w * scan_h)
  • 下采样算法：2×2 区域取均值，将 320×240 降至 160×120 供 quirc 处理
  • Y 通道提取后立即释放 DVP 缓冲区回队列，避免占用过久

八、Web 配置系统

8.1 架构

设备启动 WiFi AP（SSID: AIC-Banner-Config，密码: 12345678，信道 6），IP 地址 192.168.1.1，运行 DHCP 服务器，在 80 端口启动 Mongoose HTTP 服务器。

8.2 API 接口

方法 路径 功能
GET / 嵌入式 HTML 配置页面
GET /api/config 获取 Banner 配置 JSON
GET /api/commodity 获取商品配置 JSON
GET /api/navi 获取导航配置 JSON
POST /api/config 更新 Banner 配置
POST /api/commodity 更新商品配置
POST /api/navi 更新导航配置
POST /api/reset 重置为默认配置
POST /api/upload/{filename} 上传 Banner 图片（校验 494×78）
POST /api/upload/commodity/{filename} 上传商品图片（校验 80×80）

8.3 安全措施

  • 文件名白名单校验：仅允许字母、数字、.、_、-，长度不超过 64
  • Content-Length 早期拒绝：超限直接返回 413
  • 接收缓冲区限制：recv_mbuf.len > 307200 + 4096 时强制关闭连接
  • 图片尺寸校验：解析 PNG/JPEG/BMP 文件头验证宽高，不匹配则删除并返回错误
  • 价格格式校验：支持多种货币前缀，验证必须包含数字和可选小数部分

8.4 配置热更新

  1. HTTP 线程接收 POST → 解析 JSON → 写入 s_pending_json 缓冲区 → 设置标志
  2. 同时将 JSON 保存到 SD 卡文件实现持久化
  3. LVGL 定时器 200ms 轮询检测标志 → 发布事件 → 各组件执行热更新

十、系统初始化流程

custom_init() 是整个系统的组装入口，执行以下初始化序列：

  1. 初始化基础设施：event_bus、async_loader
  2. 初始化所有控件模块的对象池
  3. 等待 SD 卡挂载（最多重试 50 次，每次 100ms）
  4. 复制默认图片资源从 /rodata/image 到 /sdcard
  5. 初始化 TTF 字体（汉仪旗黑 15/18 号）
  6. 注册四种控件到 widget_factory
  7. 删除 AiUIBuilder 生成的静态控件，替换为动态组件
  8. 创建四大组件（banner、commodity、cart、navi）
  9. 绑定购物车动画、结算按钮事件
  10. 订阅 Web 配置变更事件
  11. 启动 Web 配置服务器、UART3 支付模块、QR 扫描模块
  12. 加载持久化配置（覆盖默认值）

十一、技术亮点总结

  1. AiUIBuilder + 自定义代码桥接：通过 layout_container_wrap() 将工具创建的 LVGL 对象包装为动态布局容器，既保留可视化快速原型能力，又获得运行时灵活性。

  2. 全事件驱动架构：组件间零直接依赖，购物车不知道商品卡片的实现，支付模块不知道购物车的实现，Web 配置不知道任何 UI 组件的 API。

  3. 嵌入式 Web 配置：RT-Thread 上运行 Mongoose HTTP 服务器 + WiFi AP，手机连接热点即可修改配置，无需固件升级，配置自动持久化到 SD 卡。

  4. 双支付模式：支持"用户扫码"和"设备扫码"两种模式，通过 UART3 与 PC 主机通信，实现支付宝沙箱环境下的完整支付闭环。

  5. 无锁线程间通信：UART3 使用 SPSC 环形队列，Web 配置使用 volatile 标志 + 缓冲区，均避免重量级锁开销。

  6. 内存池管理：所有高频创建/销毁的控件使用 RT-Thread 内存池，容量与业务上限对齐，避免内存碎片。

  7. 摄像头视图硬件加速：DVP 缓冲区零拷贝推送到视频层，UI 层半透明实现画中画效果。

  8. 组合模式 UI 树：Container 和 Widget 统一为树形结构，支持深度优先销毁、批量更新、动态增删，使运行时热更新简单可靠。
